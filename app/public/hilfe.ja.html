Blueprint Studio – マニュアル

Satisfactory の設計図をゲーム外で表示(実際のゲームモデルによる 2D/3D)、編集し、新しい形状を作成し、すべての設計図に統一した名前を付けられます。すべてこの PC 上でローカルに動作します。

起動と概要

  • 起動: start.bat またはデスクトップのショートカットをダブルクリックします。アプリは専用のウィンドウで開きます。ウィンドウを閉じると、約 25 秒後にプログラムが自動で終了します。
  • 上部で領域を選びます: 設計図(表示/編集)、建物カタログ(全パーツとそのデータ)、整理(名前の統一)、ヘルプ(このページ)。
  • フォルダーは現在の設計図フォルダーをエクスプローラーで開き、設定はパスを設定し、保存は変更を保存します。

重要: ゲームは設計図をセーブデータのロード時に読み込みます。保存や名前変更の後はセーブデータを再ロードしてください。編集はゲームを閉じているか、メインメニューにいるときに行うのが最適です。

設計図を開く

左のフォルダー選択には、SaveGames\blueprints 以下のすべてのフォルダーがサブフォルダーも含めて(インデント表示、例: Sortieren › Chaos › Kreativ)表示され、その下にライブラリフォルダーが並びます。フォルダー _Ablage、_Duplikate、_Archiv、_Pakete はそこには表示されません。数千の設計図を含むフォルダーもすばやく開けます: リストはスクロールに合わせて読み込まれ、検索と選択(Shift でリスト全体にわたる範囲選択も可)はすべての項目に適用されます。

左の設計図でセーブデータ(セッション)を選びます – これは …\SaveGames\blueprints\ 内のサブフォルダーで、ゲームがあなたのワールド用に使うものです(例:「MeineWelt」– セーブデータ内のセッション名と同じ名前です)。その下に、色、サイズ、日付、説明付きですべての設計図が表示されます。検索欄は名前と説明で絞り込みます。クリックすると設計図が開きます。

パーツタブには、開いている設計図に含まれるすべてのパーツの種類が数とともに表示されます。クリックするとその種類のオブジェクトがすべて選択されます(Shift で選択に追加)。

2D ビューと 3D ビュー

2D 上面図

  • クリックで選択、Shift+クリックで追加、空いている場所をドラッグ = 範囲選択。
  • 選択したものをドラッグ = 移動(設定したグリッド単位)。右/中マウスボタン = ビューを移動、マウスホイール = ズーム。

3D ビュー

  • 左マウスボタンでドラッグ = 回転、右マウスボタン = 移動、マウスホイール = ズーム、クリック = 選択。
  • W A S D を押し続ける = 前 / 左 / 後ろ / 右へ移動(視線方向に水平移動、高さは変わりません)。Shift で 3 倍速。速度はズームに合わせて変わります。
  • モデル(上部のスイッチ): 実際のゲームモデルを表示します – 機械、基礎、壁、屋根、梁、ガラス(半透明)。オフ: シンプルな箱(非常に大きな設計図で高速)。
  • モデル表示ではコンベアベルトはスプラインに沿った側縁付きの平らなベルトとして、コンベアリフトは枠付きの開いた縦穴として描画されます。パイプとハイパーチューブはチューブとして、線路はセグメントとして描画されます。(「モデル」なし: シンプルなブロック。)
  • ペン(上部のボタンまたは P キー): 左マウスボタンを押したまま範囲を自由に囲むと、その中のものがすべて選択されます。開始時に Shift = 追加、Ctrl = 除外。ペンモードでの回転は右マウスボタンで行います。通常は見えているオブジェクトのみが対象です。「隠れたオブジェクトも」を使うと、中心点が範囲内にあるものすべて(背後や下にあるものも)が対象になります。階層を選択している場合はその階層のみが対象です。その後 Del または「n 件を削除」。「完了」または Esc でペンを終了します。
  • モデルはゲームから取り出したもの(FModel エクスポート、FModel 参照)で、変換済みのものが app\public\modelle にあります。

階層

複数階建ての設計図では、アプリが基礎の階層を認識します。「階層 2」は階層 2 を表示し、下の階層は薄く表示され、上の階層は非表示になります。

X、Y、Z 軸での回転 / 傾斜

ツール回転 / 傾斜(ツールバーの座標軸アイコン): 軸を選びます – X は前後に傾け、Y は横に傾け、Z は Q/E と同様に回転します – そして角度(−90°、+90°、180° または独自の値)を選びます。選択範囲に、何も選択していない場合は設計図全体に適用されます。「その後再び地面に置く」は下端を維持します。例: 縦向きに作った交差点を、路面が上に来るまで X または Y で 90° 傾け、新しい設計図として保存します。3D ビューでは下から見ることもできるようになりました。

オブジェクトを非表示にする

隠れたパーツや背後のパーツに手が届くように: 選択して非表示(斜線の入った目、H)– または選択のみ表示(I)を使うと、それ以外がすべて消えます。非表示のオブジェクトはクリックできず、2D でも 3D でも描画されません。ボタン「… 個を非表示 · すべて表示」(または Shift+H)ですべて元に戻ります。非表示は設計図を変更せず、保存もされません。

多数の階層

階層が 11 以上になると、バーはコンパクトに表示されます: 最初の階層 · 選択中の階層の上下 5 階層ずつ · 最後の階層、さらに矢印 ‹ › と、全階層とその高さの一覧。

右のインスペクターには、選択したオブジェクトの名前、位置、回転、寸法、電力、レシピ(毎分の量付き)、カラーパターン、ティア、建設コストが表示されます。何も選択していないときは、設計図全体のデータと建設コストが表示されます。

素材 / バリエーション / Mk 段階の交換

オブジェクトを選択し(例: 「パーツ」タブ → すべての基礎)→ 右の素材 / バリエーションを交換 …。同じ寸法のバリエーションが提示されます(コンクリート → アスファルト、グリップメタル、ガラス、標準の壁 → 窓付きの壁 …)。建設コストとレシピリストは保存時に再計算されます。* 付きのパーツは関連パーツから派生したものです。機械(接続口/インベントリ付き)は交換できません。

Mk 段階の変更(コンベアベルト、コンベアリフト、パイプ、ポンプ)

ベルト/リフトを選択し(「パーツ」タブ → 例:「コンベアベルト Mk.5」をクリック)→ 素材 / バリエーション / Mk 段階 … → 希望の段階を選びます(Mk.1–Mk.6、パイプは Mk.1 ↔ Mk.2、流量表示なしのものも可、ポンプは Mk.1 ↔ Mk.2)。経路、接続口、接続はすべてそのまま維持され、種類と建設レシピだけが置き換えられます。設計図のレシピリストは追加されます。ただし設計図ヘッダーに表示される建設コストはベルトについては再計算されません(ゲームが配置時に自ら計算します)。その段階がセーブデータで解放されている必要があり、そうでないと設計図を建設できません。

形状ジェネレーター

左の形状タブ: 円形プレート(ゲーム内と同じリング)、グリッド上の円、リング / 円軌道、長方形の範囲、建物(壁、窓の列、屋根付きの多層)、円形タワー。サイズ、階数、パーツ(コンクリート、アスファルト、ガラス …)を選べます。

  • 新しい設計図として開く – プレビュー。値の変更はすぐに反映されます。その後いつも通り編集して保存します。
  • 開いている設計図に挿入 – 形状を開いている設計図の上に配置します(選択状態、矢印キーで移動)。
  • 画像からピクセルアート：画像（PNG、JPG、GIF …）、ピクセル単位の幅、ピクセルサイズ（0.5 / 1 / 2 m）、壁か床、必要なら発光を選びます。各ピクセルが画像の色の正方形の看板になります（コミュニティのピクセルアート設計図と同じ）。透明なピクセルは省けます。設定の下に縮小画像が表示され、3Dで見るで壁を表示、設計図として保存で保存します。最大20,000ピクセル – 色のはっきりした小さな画像が最適です。
  • 間取り図から建物（画像）：グリッド上に間取りを描きます（例：ペイントで、1マス＝8 × 8 mの土台1枚）– 黒線＝壁、青＝窓、赤＝ドア、隙間＝開いた通路。画像を選び、「幅（土台）」を画像の横幅のマス数に合わせます。確認画像にグリッド、認識した壁/窓/ドア、緑で床（閉じた外壁の内側すべて）が表示されます。続いて階数、階の高さ、パーツを選びます。窓とドアは各階の一番下の壁列に入ります。配置時に画像を見るのと同じ向きを向くと、画像の上側が設計図の奥になります。

保存

  • 新しい設計図として保存(推奨): 同じセーブデータフォルダーに新しい名前でコピーを作成します。説明とアイコンを含む .sbpcfg も一緒に作成されます。
  • 元を上書き: 事前に元のファイルが userdata\sicherungen\ にバックアップされます。
  • 編集していないデータ(レシピ、色、接続 …)はすべてバイト単位でそのまま維持されます。
  • ライブラリやサブフォルダーにある設計図(「整理」から 👁 で開いたもの)も編集できます。コピーは元と同じフォルダーに作成されます。

建物カタログ

ゲームデータ(CommunityResources\Docs\de.json)にあるすべての建物: カテゴリ、解放済みティア、建設素材、寸法、電力、建設コスト、そして毎分の量付きのすべてのレシピ。左でカテゴリ、ティア、素材による絞り込みができます。「建築バリエーションを表示」は、基礎や壁などの全素材バリエーションも表示します。アイコンは FModel エクスポート(app\public\icons)から取得されます。

整理 – すべての設計図に統一した名前を付ける

整理領域はすべての設計図を読み込みます: SaveGames\blueprints 以下のすべてのセーブデータフォルダー(サブフォルダーを含む)と、設定のライブラリフォルダー(例: …\Meine Blaupausen)です。_Archiv、_Pakete、_Duplikate という名前のフォルダーはスキップされます。

  1. 読み込み: 初回は数に応じて 20–60 秒かかりますが、2 回目以降は高速です(キャッシュ)。
  2. 提案の確認: 各設計図に新しい名前が表示されます(命名規則に準拠)。理由「名前から」= 古い名前から導出。「内容から」= 古い名前に意味がなかった(例: 2025_10_10 13_40_24)ため、内容(製品、機械、パーツ、寸法)から提案したもの – これらは特によく確認してください。フィルター「内容からの名前(要確認!)」でこれらだけを表示できます。
  3. 表示: 目のアイコン 👁 で設計図を 2D/3D で開きます(閲覧のみ)。「整理」領域から戻れます – 入力内容は保持されます。
  4. 調整: 新しい名前を行の中で直接変更します。赤枠 = 命名規則に合っていません(長すぎる、使用禁止の文字、グループコードなし)。自分で行った変更はアプリを閉じてもすぐに記憶されます。
  5. 重複と類似: アプリは名前だけでなく内容も比較します: どのパーツがどの位置にあるか(1 m グリッド、設計図の位置には依存しません)。
    • 同一(≥ 99 % 一致)で同じフォルダー内: 名前の付け方が劣る方が「重複」として提案され、適用時に _Duplikate へ移動されます – 削除はされません。ゲームはサブフォルダーを認識しません。
    • 非常に類似(90–98 %): ヒントのみ(「… と 93 % 類似」)。例: 看板がいくつか多いバリエーション。判断はあなた次第です(アクションを「重複」にするか、名前を変更)。
    • 異なるフォルダー(ゲームとライブラリ)にある同じ設計図には、同じ名前が付けられます。
    フィルター「重複と類似(プレビュー付き)」は、各項目の横に 2 つの小さな上面図を表示します: 左がこの設計図、右が同一/類似の設計図 – 本当に重複しているかすぐに分かります。
  6. 適用: チェックを入れ(初期選択: 未処理のものすべて)→ 選択項目を適用。.sbp と .sbpcfg が一緒に名前変更されます。
  7. 元に戻す: 履歴 / 元に戻すに各操作が表示されます。クリック 1 回で古い名前と場所がすべて復元されます。

適用する前にゲームを閉じるか、メインメニューにしておいてください。ヒント: 段階的に作業しましょう – 例えばまずフィルター「場所: ライブラリ」、次にグループを 1 つずつ。

アクション・事前振り分け・保管庫への移動

  • 行ごとのアクション：名前を変更（または変更不要）、振り分け（名前はそのまま、フォルダーだけ変更）、重複 → _Duplikate、削除 → ごみ箱（Windows のごみ箱へ。そこから復元可能）。フィルター「振り分けのみ」「削除のみ」でこれらだけを表示します。
  • 重複は、パーツが同一（種類と数が同じ）で形が 99 % 以上一致する場合だけ提案されます。パーツが少し多い大型建築の途中段階は「類似」扱いです。
  • ライブラリでの事前振り分け：ライブラリの受信フォルダー（名前が「_」で始まるもの。例：_sortieren）の設計図は、適用時にそのフォルダーの中に保管庫と同じ構成で振り分けられます（例：_sortieren\1 Bauen\1_3 …）。振り分け先は新しい名前の下に表示されます。重複はすべて _sortieren\_Duplikate へ（同名は「(2)」付き）、空になったフォルダーは Windows のごみ箱へ移ります。
  • 保管庫へ移す（n）：振り分け済みのものを同じフォルダー構成のままゲームフォルダーの保管庫へ移動します。同じ名前が既にある場合、その設計図はライブラリに残り、報告されます。
  • 名前変更・振り分け・重複は履歴／元に戻すから、削除は Windows のごみ箱から元に戻せます。

保管庫 – 設計図の振り分けとオン/オフ

設計図領域の下部に保管庫があります(矢印で開閉)。左には命名規則に沿ったフォルダー(1 建設 … 9 特殊 とそのサブグループ)と、あなたの独自フォルダー(◆)が並びます。

  • 保管: 左のリストから設計図をフォルダーへドラッグします。設計図はセーブデータフォルダーから取り出され、…\SaveGames\blueprints\_Ablage\<フォルダー> に移動されます。その後ゲームからは見えなくなります。フォルダーは中に何かが入ったときに初めて作成されます。
  • ゲームに入れる: 設計図の横のスイッチをクリックします(緑 = ゲーム内)。設計図は元のセーブデータフォルダーに戻ります。フォルダーのチェックボックス(左)や「すべてゲームへ / すべて保管」を使うと、フォルダー全体(サブフォルダーを含む)に対して行えます。
  • ゲームに入れる – どのセーブデータへ? ゲームは blueprints\<セーブデータ> 内の設計図だけを表示します(フォルダー名はセーブデータ内のセッション名と同じです。例: MeineWelt)。アプリはセーブデータからセッション名を読み取ります。設定 → 「ゲームに入れる」先のセーブデータで 1 つを固定できます。「毎回確認」にすると、有効化するたびに全セーブデータの選択肢が表示されます(「標準として記憶」付き)。Bauen や Deko のようなまとめ用フォルダーはセーブデータではありません – 有効化した設計図がそこにある場合、保管庫に「⚠ ゲーム外」と表示されます。スイッチをオフにしてから再びオンにすると、正しいセーブデータに移されます。左のフォルダー選択では、セーブデータが独自のグループにまとめて表示されます。
  • 位置とサイズ: 設定 → 保管庫フォルダーで、保管庫を下に置くか、設計図の左側にアプリの全高で置くか(上にフォルダー、その下に内容)を選べます。幅(左配置)と高さ(下配置)はスライダーで調整できます – または保管庫の端をマウスで直接ドラッグします。端をダブルクリックすると既定値に戻ります。
  • すべて開く / すべて閉じる(保管庫の上部): すべてのフォルダーを一度に開閉します。
  • 複数を一度に: 左の設計図リストで Ctrl+クリックで個別に追加選択、Shift+クリックで範囲を選択します。リストの下に「n 件選択」と表示されます。選択した設計図の 1 つを保管庫フォルダーにドラッグすると、選択したものすべてが一緒に移動します。右クリック、Del または削除ボタンで、確認の後に選択したものすべてを削除します(ごみ箱へ)。Esc または解除で選択を解除します。
  • ライブラリから振り分け: フォルダー選択の上部、ライブラリの下に、設計図ライブラリのすべてのサブフォルダー(例: …\Meine Blaupausen)が個別に表示されます。そこから設計図を保管庫フォルダーにドラッグすると、…\SaveGames\blueprints\_Ablage\<フォルダー> にコピーされます – 元のファイルはライブラリに残ります。有効化すると、最後に選んだゲームセッションに移されます。
  • 並べ替え: 保管庫の設計図を別のフォルダーへドラッグします。左のリストへドラッグすると有効化されます。
  • 独自フォルダー: 「+ 独自フォルダー」または「+ サブフォルダー」。空の独自フォルダーは削除できます。
  • 表示: ダブルクリックまたは「表示」。保管中の設計図は表示のみです。編集するには、まずゲームに入れてください。

何も削除されることはなく、移動されるだけです(.sbp と .sbpcfg を一緒に)。どの有効な設計図がどのフォルダーに振り分けられているかは、アプリが userdata\ablage.json に記憶します。ゲームの実行中は、セーブデータを再ロードするまで変更は反映されません。

設計図の削除

名前と保管庫の右上にあるごみ箱ボタン、保管庫内の設計図のごみ箱、または左のリストで設計図を右クリックします。確認の後、設計図は(.sbpcfg と一緒に)Windows のごみ箱に移り、そこから復元できます。それができない場合は userdata\papierkorb に移されます。

名前の提案

設計図を開くと、右上の名前と保管庫に命名規則に沿った提案が表示されます – 3 つの欄に分かれています: カテゴリ _ サブカテゴリ _ 名前。アンダースコアはアプリが自動で入れます(名前内のスペースもアンダースコアになります)。「カテゴリ」をクリックするとすべてのカテゴリ(1 建設 … 9 特殊)が、「サブカテゴリ」をクリックすると選んだカテゴリのサブグループが表示されます – クリックで反映、または自分で入力することもできます(入力でリストを絞り込み、矢印キー + Enter で選択)。その下に、文字数カウンター付きの完成した名前が表示されます(最大 32 文字)。「保管」は選んだカテゴリに従います。名前を変更すると同時に振り分けも行われます: 設計図はすぐに対応する保管庫フォルダーに入ります(ゲームから: 保管、ライブラリから: コピー、保管庫から: 移動)– 設定でオフにできます。「保管」は名前を変更しない設計図のために残されています。番号付きの独自フォルダー(例: 2 生産 の下の 2_7 Wasseraufbereitung)は、選択肢と保管庫の中で順序どおりの正しい位置に表示されます(末尾に「独自」マーク)。名前を変更はファイル名を変更し、保管はそれを対応するフォルダーにすぐ置きます。提案はあなた自身の名前から学習します:

  1. 設計図が、すでに適切に名前が付いた設計図と ≥ 90 % 同じ場合、そのグループが採用されます(100 % の場合は「重複の可能性」というヒントが出ます)。
  2. 名前の中の、あなたが特定のグループでよく使っている単語(例:「案内標識」→ 4_7)がグループを決めます。
  3. 意味のない名前(日付、「新規」…)の場合は、あなたの設計図との内容の類似性が考慮されます。
  4. それ以外の場合は、「整理」領域の固定ルールが適用されます。

ここや「整理」で行ったすべての名前変更は、次回以降の提案に反映されます(userdata\namen-gelernt.json)。

大きなウィンドウ・タイル・表示／非表示

  • 大きなウィンドウ：保管庫の上部にある大きなウィンドウボタン – 小さな画面で便利です。左にフォルダー、右に中身。操作はいつもどおりです。✕、Esc、または外側のクリックで閉じます。
  • リストかタイル：大きなウィンドウの上部で切り替えます。タイルでは各設計図を小さな3Dプレビュー（有効なら実際のモデル）で表示します。タイルをクリックすると設計図が開き、ウィンドウは閉じます – 再表示は「大きなウィンドウ」から。選択は記憶されます。
  • 保管庫を隠す：「フォルダー」の横の保管庫を隠すボタンでフォルダーバー全体を隠せます（2D/3D の表示領域が広がります）。同じボタン（保管庫を表示）で戻ります。
  • 上部のフォルダーは常に設計図のメインフォルダー …\SaveGames\blueprints をエクスプローラーで開きます。
  • 非表示のとき：保管庫を隠している間は、上部の横に大きなウィンドウボタンが表示され、保管庫を直接大きなウィンドウで開けます。
  • 編集：保管庫の設計図はそのまま編集できます（回転、移動、交換など）。保存するとコピーが同じ保管庫フォルダーに入ります。上書きする場合は先にバックアップが作られます。
  • 複数選択：保管庫のファイル一覧でクリックすると設計図を選択、Ctrl+クリックで個別に追加・解除、Shift+クリックで範囲選択、Ctrl+Aで全選択。選択した設計図はまとめてフォルダーや左のリストへドラッグできます。上のバーにはゲームへ、保管、削除（Delでも可）、解除（Escでも可）があります。
  • 移動時の名前変更：設計図を別グループのフォルダーへドラッグすると（例：1_1から2_6）、名前の先頭のグループコードを調整します：1_1_Haus → 2_6_Haus。テーマ用サブフォルダーは親フォルダーのコードを使い、コードのない名前やフォルダーは変わりません。

ゲーム内のカテゴリ（設計図メニュー）

保管庫から設計図をゲームへ戻すと、アプリはゲームの設計図メニューでもすぐに振り分けます：メイングループ → カテゴリ、サブグループ → サブカテゴリ。保管庫のテーマ別サブフォルダーはゲームにはありません。ゲームはこの分類をセーブデータの中に保存するため、アプリはそのセッションの最新のセーブデータ（多くはオートセーブ）を変更し、事前に一度だけ元のファイルを userdata\sicherungen\spielstaende にバックアップします。

  • ゲームは閉じておく：ゲームの起動中は変更を記憶し、終了したらすぐに反映します（アプリは開いたままにしてください）。その後、最新のセーブデータを読み込みます。
  • アイコン：ゲーム内でカテゴリごとに一度アイコンを設定してください（「変更」）。アプリは次回それを読み取り、新しいセーブデータにも使います。既定は家のアイコンです。
  • ゲーム内で自分で作ったカテゴリはそのまま残ります。グループのない設計図は「未分類」に入ります。

プランナー – 生産チェーンの計算と作成

プランナーでは左側で、作りたいもの（+ 目標、毎分の数量）と既に完成品で届くもの（+ 供給、例：隣のベルトから鉄インゴット 120/分）を入力します。アプリがすべての生産段階・機械・原料・必要電力を計算します。

  • グラフ／リスト：グラフはチェーンをボックスで表示します。ボックスをドラッグ＝移動、クリック＝レシピ選択（代替レシピも可。ゲーム内で解放が必要）、背景ドラッグ／ホイール＝表示。大きなチェーンには合わせると並べ直すが便利です。標準レシピに戻すですべてのレシピをリセットします。
  • 設計図を作成 …（またはボックスの ▣）：工場全体（列を上下に重ね、ベルトとコンベアリフトで接続）、ある段階までの部分工場、またはスプリッター・マージャー・基礎・電力・看板付きの機械列としての単一の段階を選べます。名前・セーブデータ・ベルトの上限を選び、先に3Dで確認してから設計図として保存します。
  • 基データ：プランナーで作った設計図を開くと、そのプラン（「設計図の基データ」）が表示されます – 自分のプランとして採用または自分のプランに戻る。
  • 配置：自分の設計図で測った通りのコンパクト配置 – 機械は隣接、スプリッター／マージャーは接続口の2 m手前、追加ラインは4 m外側・2 m高く、パイプは常にコンベアの上。各機械の前、ラインの外側に電柱。コンベア・リフト・パイプは全機械100 %（計画分だけでなく）に合わせて選ばれ、列間の接続は供給側の全量を運べます。
  • パイプと液体：角のあるパイプ経路はゲームと同じく曲がり付きの1本のパイプ。2つの列が隣り合っていれば直接つなぎ、そうでなければ右側のパイプ列を通ります。パイプが9 mより高く上がる場合はプランナーがポンプ（電力付き、非常に高い場合はMk.2）を設置。液体の副産物は流体バッファーへ、固体はAWESOMEシンクへ。
  • 水と複数の供給元：同じ素材が複数の列から来る場合はすべて接続（コンベアはそれぞれマージャー、パイプはそれぞれ上からジャンクション）。工場内で生じるもの（例：アルミチェーンの水）を先に使い、不足分だけ外部から – パイプでは接続口が上向きのジャンクション経由（看板「ZULAUF VON OBEN」）。ダイアログの水抽出機も建設をオンにすると、不足する水のために電力付きの水抽出機を横に配置（各120 m³/分、ゲームでは設計図経由でのみ可能）。
  • 制限：一部の建物にはまだ列の設計がありません（グレー表示、マウスで理由を表示）– そこには看板付きの自由な入出力ができます。プランナーが作った設計図は部品テンプレートに使われません。テンプレートのインベントリにアイテムがある場合は、ゲームで空の建物の設計図を保存してください。

マスタークラス – 完成済みの手本工場

プランナーのマスタークラス …は、きれいに組まれたテンプレート工場をティア（必要な最上位マイルストーン）とテーマ別に表示します。元データはマスタークラスのフォルダー（既定：blueprints\Sortieren\Tschukki と保管庫「10 Master Class」）です。

  • テンプレートをクリック：最終製品・供給・機械を表示。3D で表示、ゲームへコピー（セーブデータへ）、目標として使う（最終製品がプランナーの目標になります）。
  • 保管庫へ振り分けで、すべてのテンプレートを「10 Master Class」の下にテーマ別・名前にティア付きで整理します。
  • パッケージを保存／パッケージを読み込む：すべてのテンプレートを1つのファイル（.bsmc）に保存し、別のPCで読み込めます。

言語

設定 → 言語で Deutsch、English、Français、日本語 を選べます。アプリはその後再読み込みされ、このヘルプも4言語すべてにあります。設計図やフォルダーの名前はそのままです。保管庫フォルダーの名前、つまりゲーム内のカテゴリの名前は、保管庫の構成（設定 →「構成を編集 …」）で選んだ言語になります。カテゴリのアイコンはグループ番号ごとに記憶されるため、言語を変えても残ります。

マップ – セーブデータを見る

マップ領域は、…\FactoryGame\Saved\SaveGames\<番号> にあるセーブデータ(.sav、Update 8 からバージョン 1.2 まで – 非常に大きな古いセーブは開くときに多くのメモリが必要です)を読み込み、建設したものすべてを上面図で表示します: 建物、基礎、壁、柱(ゲームがまとめて保存する「軽量」パーツも含む)、コンベアベルト、パイプ、線路、ハイパーチューブは線として、さらに電線とあなたのキャラクター(赤い十字)。

  • 左でセーブデータを選びます。初回は読み込みに数秒かかります。その後はファイルが変わらない限りキャッシュ(userdata\karten)から読み込まれます。
  • ドラッグ = 移動、マウスホイール = ズーム、クリック = パーツを表示(名前、位置、高さ、セーブデータ内の数)。「合わせる」はあなたの建築物を、「ワールド全体」はマップ全体を表示します(グリッド = 500 m)。
  • 左で階層のオン/オフを切り替えます(例: 基礎をオフにして機械を見る)。資源ノードは最初はオフです。
  • パーツを強調: 検索欄に名前を入力します(例:「製作機」)– 一致するパーツは色付きのまま、床は暗く表示されます。右の「よく使われるパーツ」はクリックできます。
  • マップ(上部のチェック): ゲームワールドを背景に表示します。4 枚のタイルは userdata\kartenbild にあります(Map_0-0 … Map_1-1、各 3.75 × 3.75 km)。
  • 高さ 下限 – 上限(メートル): この範囲内のパーツだけを表示します。例: 大きな工場の 1 フロアだけ。
  • 右の種類別の建物: すべての機械、発電機、保管、鉄道などとその数。チェックを入れるとそれらが強調され、それ以外は暗くなります(複数チェック可。グループのチェックでグループ全体、例: すべてのパイプ)。上部の「すべて通常」または Esc で元に戻ります。
  • 3D で開く: セーブデータを 3D エディター「Satisfactory 3D Map」で開きます(下記参照)。

マップ自体はセーブデータを変更しません。

範囲を設計図として切り出す

  1. セーブデータを開き、階層と高さ 下限 – 上限で含めるものを設定します(例: 基礎を非表示にする、または 1 フロアだけ)。
  2. ツールを選びます: 長方形(ドラッグで描く。いつでも Shift + ドラッグでも可)またはペン(マウスボタンを押したまま範囲を自由に囲む – 離すと形が閉じます)。
  3. 右にサイズとパーツ数が表示されます。3D で表示は切り出した範囲をすぐにアプリの 3D ビューで表示します(ゲームモデル付き、何も保存されません)。設計図として保存は選んだフォルダーに保存します。「設計図で開く」で結果を表示します。
  • 建物(機械、ベルト、パイプ、保管、看板 …)は 1:1 でそのまま取り込まれます – レシピ、設定、接続口、範囲内の接続も含みます。
  • 基礎、壁、柱、梁はゲームがまとめて保存します(「軽量」)。これらはあなたの設計図テンプレートから再構築されます。梁の長さは維持されますが、色/パターンは維持されません。テンプレートのないパーツはスキップされ、報告されます。
  • 電線は両端が範囲内にある場合のみ取り込まれます。範囲外のパーツへの接続は失われます。
  • 設計図は範囲の中心(8 m グリッド)と下端 0 に揃えられます。大きな範囲には、ゲーム側で Blueprint Designer Plus などの Mod が必要です。
  • Megaprint からは(まだ)できません – その場合はセーブデータを使ってください。

自分のゲームのマップ画像(FModel)

  1. FModel(FModel 参照)で FactoryGame/Content/FactoryGame/Interface/UI/Assets/MapTest/SlicedMap に移動します。
  2. 4 つのテクスチャ Map_0-0、Map_0-1、Map_1-0、Map_1-1 を選択 → 右クリック → Save Texture(PNG)。
  3. werkzeuge\kartenbild-uebernehmen.bat を実行します。FModel のエクスポートから画像を探し、userdata\kartenbild に配置します(古い画像は .alt として残ります)。

3D エディター「Satisfactory 3D Map」

moritz-h による独立したオープンソースプログラム(GPL-3.0)で、セーブデータのすべてのオブジェクトを 3D で表示し、そのプロパティを編集できます。Blueprint Studio は選んだセーブデータでこれを起動するだけです。

  1. github.com/moritz-h/satisfactory-3d-map/releases から最新の Windows 版をダウンロードします(1.2 のセーブデータには v0.10 以降)。
  2. 展開します。例: werkzeuge\Satisfactory3DMap へ – そこならアプリが自動で見つけます。別の場所にある場合: 設定 → 3D エディターにフォルダーまたは .exe を入力します。
  3. マップでセーブデータを選択 → 3D で開く。

Blueprint Studio は起動時に 3D エディターを、あなたのゲームファイルから実際のゲームモデルを読み込むように設定します(設定でオフにできます)。そのためにはファイル oodle-data-shared.dll が必要です。アプリはこれを FModel フォルダーから自動でコピーします(FModel は初回起動時に自分でダウンロードします)。ファイルがない場合、エディターはゲームモデルなしで起動します。3D エディターは独自のウィンドウを持つ別のプログラムです – ウィンドウを切り替えずにすばやく見たい場合は、マップの「3D で表示」を使ってください。

注意: そこでの変更は自分で保存します。事前にセーブデータをバックアップし、同じセーブデータをゲームで同時に開かないでください。

Megaprint (.cbp)

Megaprint は satisfactory-calculator.com からのエクスポートです(拡張子 .cbp、すべてのオブジェクトを位置とプロパティ付きで含む圧縮 JSON)。マップはこれらをセーブデータの下に一覧表示し(フォルダーは設定で指定。例: …\Megaprints、_Archiv を除く)、ワールドマップ上の元の位置に表示します – 階層、強調、「種類別の建物」も使えます。非常に大きな Megaprint(400 MB の JSON、300,000 パーツ)も約 2 秒で読み込めます。ただし、ベルトとパイプは今のところ線ではなく点として表示されます。

重複とごみ箱

整理 → 「重複とごみ箱」領域では:

  • 重複: 整理の際に _Duplikate へ移動されたすべての設計図(ゲームフォルダーとライブラリ)。戻すで元のフォルダーに戻します。その名前がすでに使われている場合、アプリが新しい名前を尋ねます。
  • 削除済み: アプリで削除したすべての設計図(元の場所と日時付き)。Windows のごみ箱にあるものはそこで復元します(「Windows のごみ箱を開く」)。代わりに userdata\papierkorb にあるものは、ここで直接復元できます。
  • アプリ内で完全に削除されるものはありません – 必要に応じて自分で行ってください(ごみ箱を空にする、またはエクスプローラーで _Duplikate フォルダーを削除)。
  • 整理の実行全体は、引き続き履歴 / 元に戻すで取り消せます。

セットアップ(アシスタント)と配布

初回起動時にはセットアップアシスタントが開きます(いつでも再起動可: 設定 → セットアップアシスタント)。数ステップで必要なことをすべて案内します:

  1. 言語 – Deutsch(標準)、English、Français または 日本語。建物やアイテムの名前も、あなたのゲームからその言語で取得されます。後から 設定 → 言語 で変更できます。
  2. フォルダー – セーブデータフォルダー(標準: %LOCALAPPDATA%\FactoryGame\Saved\SaveGames)と Satisfactory のインストール先。アプリは Steam ライブラリ、Epic、全ドライブを自動で探します。「選択 …」で Windows のフォルダーダイアログが開きます。緑のチェック = 検出済み。任意: 独自の設計図コレクションと Megaprint フォルダー。
  3. セーブデータ – 「ゲームに入れる」で設計図をどのセーブデータに置くか(または毎回確認)。
  4. 3D 表示 – シンプルな箱(すぐに完了)または実際のゲームモデル。
  5. ゲームモデル(「実際のゲームモデル」を選んだ場合のみ)– 「モデルを自動で取得」をクリックするだけで自動: 初回はアプリが Microsoft の無料の .NET 10 SDK をインストールし(Windows が許可を求めることがあります)、無料ライブラリ CUE4Parse(FModel と同じもの)をダウンロードして小さな補助プログラム(werkzeuge\extraktor)をビルドし、それを使ってパーツデータ・3D モデル・アイコンをゲームのインストールから直接取り出します。進行状況と出力はウィンドウに表示されます。初回は約 5〜15 分、以降はずっと速くなります。うまくいかない場合は、その下に FModel を使う手動の手順も残っています(.NET デスクトップランタイム 10 をインストール、FModel をダウンロード、値を入力 – それぞれコピーボタン付き –、3 つのエクスポートをクリック、「取り込み」)。
  6. その他 – マップ画像、3D エディター「Satisfactory 3D Map」、デスクトップのショートカット。

さらに設定 → 前提条件とショートカットで、いつでも次を確認できます: Node.js、ゲームのインストール、セーブデータフォルダー、アプリのウィンドウ(Edge/Chrome)、3D モデル、アイコン、マップ画像、3D エディター、デスクトップのショートカット – ワンクリックで追加インストールできるもの:

  • 3D エディター「Satisfactory 3D Map」– GitHub から最新の Windows 版を werkzeuge\Satisfactory3DMap へ。
  • マップ画像 – satisfactory-3d-map プロジェクトの 4 枚のタイル(0.6 時点。最新の状態にするには FModel で置き換えてください)。
  • デスクトップのショートカット – デスクトップとスタートメニューに、アイコン付きで。

Node.js は初回起動時に start.bat が自動でインストールします(winget)。3D モデルとアイコンは Coffee Stain Studios のゲームコンテンツです: 一緒に公開してはならず、各ユーザーが自分のゲームインストールから一度取り出します – アシスタントで自動、または FModel で手動(FModel の手順)。

アップデート

Blueprint Studio は起動時(最大 6 時間ごと)に GitHub で新しいバージョンを探します。見つかると上部に ⬆ アップデート ボタンが表示されます: 新機能を表示し、今すぐアップデートでインストールします。その後アプリは再読み込みされ、サーバーも自動で再起動します。手動の場合: 設定 → アップデート → 今すぐアップデートを確認。

  • 保持されるもの: 設定と userdata 内のすべて、設計図、3D モデル、アイコン、FModel、3D エディター、抽出ツールのファイル。
  • バックアップ: 置き換えられるプログラムファイルは事前に userdata\update-sicherung\<旧バージョン> にコピーされます – 元に戻すには、これらのファイルをプログラムフォルダーにコピーし直すだけです。
  • 取得元: GitHub プロジェクトのリリース(app\update.json に設定)。設定で別の取得元を指定できます。自動確認もそこでオフにできます。

公開(例: GitHub)

プログラムフォルダー内のファイル .gitignore は、公開してはならないものや個人的なものをすべて除外します: userdata、モデル、アイコン、マップ画像、FModel、3D エディター、設計図/セーブデータ。ヘルプには固定のパスは含まれておらず、常にあなた自身の設定にあるフォルダーを表示します。

アップデートの公開: app\server.mjs(VERSION)と app\public\js\main.js(APP_VERSION)のバージョン番号を上げてアップロードし(GitHub Desktop: Commit → Push)、GitHub の Releases → Draft a new release でタグ v + バージョン番号(例: v1.1.0)と新機能の短い説明を付けてリリースを公開します。インストール済みのすべてのアプリが次回起動時にアップデートを提案します。

設定

  • セーブデータフォルダー(blueprints を含む): 標準 %LOCALAPPDATA%\FactoryGame\Saved\SaveGames。
  • Satisfactory のインストールフォルダー(CommunityResources を含む): あなたの場合: …\steamapps\common\Satisfactory(初回起動時に検索されます)。
  • 追加の設計図フォルダー(ライブラリ): 1 行に 1 つ。例: …\Meine Blaupausen。「整理」の対象に含まれます。
  • 言語: Deutsch、English、Français、日本語 – 変更後、アプリが再読み込みされます。
  • 保管庫のフォルダー構成(「構成を編集 …」): すべてのメイングループ(7)とサブグループ(7_3)の一覧 – 初期状態は同梱の構成とあなたの番号付き独自フォルダーです。名前の変更、項目の追加(「+ メイングループ」、「+ サブ」)や削除ができます。「既定値に戻す」でリセットします。保存すると、保管庫の既存フォルダーが対応して名前変更されます(中身はそのまま)。削除した項目のフォルダーは消えません。番号は設計図名の先頭に付きます。
  • プレフィックス: プレイヤー名やワールド名のように、名前の提案で先頭から省く単語(カンマ区切り)。
  • アップデート: 起動時に自動確認(オン/オフ)、GitHub 上のアップデート取得元(所有者/リポジトリ、空欄 = アプリの既定)、「今すぐアップデートを確認」 – アップデートを参照。
  • 設計図を開くときのビュー: 最後に使ったビュー(標準 – 最後に 2D と 3D のどちらを使ったかをアプリが記憶)、常に 2D または 常に 3D。2D/3D ボタンや 2/3 キーでの切り替えは引き続きいつでも可能です。

制限と注意事項

  • 機械を移動しても、コンベアベルト/パイプは元の場所に残ります – つながったグループはまとめて移動してください(範囲選択)。
  • 機械は交換や新規作成ができません。できるのは建築パーツのみです。
  • 古いゲームバージョン(Update 7/8)の設計図も読み込めます。Mod のパーツは灰色の箱として表示されます。
  • ゲーム内の名前は 32 文字までに制限されています – そのため「整理」は自動で短縮します。

テーマは名前から認識されます(例:「Eisenplatten(鉄板)」→ 鉄と鋼)。どのテーマにも当てはまらない場合、設計図はグループフォルダーに残ります。ファイル _Ablage\_Struktur.txt には、フォルダーと想定される割り当てが記載されています。

ルールと例

  • 最大 32 文字(ゲーム内の入力上限)。文字 \ / : * ? " < > | は使えません。ウムラウトなどの特殊文字は使えます。
  • アンダースコアで各部分を区切ります。単語は大文字で始め(Leergebäude_Japanisch12)、小さな接続語は小文字のままにします(Beton_für_Stahlbeton)。
  • 数量は末尾に: 10x Band → 2_2_Band_10x。比率はコンパクトに: Balancer 4 zu 4 → 2_3_Balancer_4zu4。
  • 生産: 製品を先に、次に機械/レート: 2_1_Eisenbarren_10xSchmelze、2_1_Platine_5x_150pm(pm = 毎分)。
  • 複数パーツのセットはセット名を維持します: 8_6_COC_Kran_2_Teil2、1_1_HouseBeckenbauer_2Teil_Turm_Links。
  • 個人用プレフィックス(例: プレイヤー名_、ワールド名_ – 設定の「プレフィックス」に入力。ほかに 270_)は省かれます – グループの方が多くを語ります。コミュニティの名前は元の言語のまま、整理だけされます(「[1.2 Vanilla]」、「v1.1」、「by …」を除去)。
  • 重複には独自の名前は付けられず、_Duplikate へ移動されます。

ゲームのアップデート時(バージョン変更)のチェックリスト

Satisfactory の大きなアップデート(例: 1.2 → 1.3)の後は、次の手順を順番に行ってください。小さなパッチなら通常は手順 1–3 だけで十分です。

  1. アプリを起動してカタログを確認する。 Blueprint Studio は、CommunityResources\Docs\de.json が変更されていれば起動時に再読み込みします。「建物カタログ」領域の左下に、建物/アイテム/レシピの数が表示されます。エラーが表示された場合: 設定 → インストールフォルダーを確認してください。
  2. 新しいゲームで保存した設計図を開く。 新しいゲームバージョンではファイル形式が変わることがあります。開ければ問題ありません。開けない場合: メッセージを控えてください – リーダー(app\lib\sbp.mjs)の修正が必要です。
  3. テンプレートを再構築する。 ファイル userdata\vorlagen-cache.json を削除し、アプリを再起動します。これによりアプリは、現在の設計図/セーブデータから新しいパーツを学習します(形状ジェネレーターと交換用)。
  4. 形状/交換をテストする。 小さな形状を作成して保存し、ゲーム内で配置します。うまくいけば、すべて互換性があります。
  5. FModel を更新する。 最新版を fmodel.app(または GitHub リリース)から …\werkzeuge\FModel に展開します – またはセットアップアシスタントの「FModel をダウンロード」を使います。Settings で UE バージョンを確認し(Satisfactory 1.2: GAME_UE5_6 – 新しいエンジンなら対応するものを選択)、新しいマッピングファイル CommunityResources\FactoryGame.usmap へのパスを設定します。
  6. アイコンを再エクスポートする(新しいアイテム/建物がある場合のみ必要): FModel → アイコン、その後 werkzeuge\icons-uebernehmen.bat。
  7. 3D モデルを再変換する(新しい/変更された建物がある場合のみ): パーツデータとモデルをエクスポートし、werkzeuge\modelle-aufbereiten.bat を実行します。不足しているメッシュが報告されるので、それを個別に追加エクスポートします。
  8. 整理を再読み込みする。 キャッシュ userdata\ordnen-cache.json は自動で更新されます。問題がある場合は削除してください。

FModel – ダウンロードとセットアップ

FModel は Unreal Engine のゲームファイル用の無料ビューアーです。これを使って Satisfactory からアイコン、3D モデル、パーツデータを取り出します。

もっと簡単に: セットアップアシスタント(手順「ゲームモデル」)のモデルを自動で取得で、FModel なしで同じデータを取得できます。以下の手順は、自動の方法がうまくいかない場合にのみ必要です。

  • ダウンロード: https://fmodel.app/ – または GitHub のリリース: github.com/4sval/FModel/releases。手順/Wiki: github.com/4sval/FModel/wiki。
  • Mod コミュニティによる Satisfactory 向けの手順: docs.ficsit.app → Extract Game Files。
  • .NET デスクトップランタイム 10 が必要です(FModel が初回起動時に求めます。アシスタントならワンクリックでインストールできます)。
  1. 展開先は …\werkzeuge\FModel(セットアップアシスタントが自動で行います)。その後 FModel.exe を起動します。
  2. ゲームを追加: 「Directory Selector」ウィンドウで Undetected Game を作成します: 名前 Satisfactory、フォルダー …\steamapps\common\Satisfactory、青いプラス、OK。
  3. UE バージョン: GAME_UE5_6(Satisfactory 1.2)。表示されない場合: 「Enable custom UE versions」をオフにします。
  4. Settings → General:
    • Output Directory: …\werkzeuge\FModel\Output
    • Keep Directory Structure: オン
    • Local Mapping File: オン、パス …\Satisfactory\CommunityResources\FactoryGame.usmap
    • 任意: Custom Versions – CommunityResources\CustomVersions.json の内容を貼り付けます(ファイルは UTF-16)。
  5. Settings → Export (Models): Mesh Format = glTF 2.0 (binary)、Texture Format = PNG、Auto-Export Attached Materials = オフ(容量の節約)。OK。
  6. 読み込み: Archives タブ → Load。その後 Folders タブと Packages タブに内容が表示されます。

新しい FModel バージョンでのエクスポート: エクスポートはまずキューに入ります(ステータスバー右下の黄色い欄)。それをクリック →「Export Session」ウィンドウ → Export。カウンターに進行状況が表示されます。

アイコンのエクスポート

  1. 検索を開く: メニュー Packages → Search(Ctrl+Shift+F)。
  2. 検索: IconDesc と入力して Enter。(約 1,500 件ヒット。)
  3. すべて選択: 最初の結果をクリックし、Ctrl+A。
  4. エクスポート: 右クリック → Export → Texture。その後、右下のキュー → Export。
  5. アプリに取り込む: werkzeuge\icons-uebernehmen.bat をダブルクリックします。カタログに必要なアイコンだけをコピーし、不足しているものを報告します。
  6. 不足分を追加: ツールが /(Hub_512|Track_512|…)\.uasset$ のような行を出力します。FModel の検索で Regex アイコン(検索欄右側の 2 番目のアイコン)をオンにし、その行を貼り付けて Enter、上と同様にテクスチャとしてエクスポートし、ツールを再度実行します。

パーツデータのエクスポート(3D の対応付け用)

アプリは、どのモデルがどのパーツに属し、どのように配置されるかを知る必要があります。その情報はゲームの Build_* ブループリントにあります。

  1. 検索を開き、Regex をオンにして次を入力: 
    Buildable/.*/Build_[^/]*\.uasset$
  2. すべて選択 → 右クリック → Export → Properties (json)。これらのエクスポートはすぐに保存されます(約 590 ファイル)。

3D モデルのエクスポート

  1. 検索、Regex オン: 
    Buildable/(Factory|Building)/.*/SM_[^/]*\.uasset$
  2. すべて選択 → 右クリック → Export → Model。キュー → Export(約 500 モデル、数分)。
  3. werkzeuge\modelle-aufbereiten.bat をダブルクリックします。パーツデータとモデルを読み込み、ゲーム座標に変換して app\public\modelle\ に書き出します(約 40 MB)。
  4. ツールが不足しているメッシュ(例: ConstructorMk1_static)を報告した場合、その名前を Regex で検索し、同様に Model としてエクスポートします: 
    Buildable/.*/(ConstructorMk1_static|SmelterMk1_static)\.uasset$
    その後、ツールを再度実行します。
  5. Blueprint Studio を再読み込みし、3D ビューでモデルスイッチを使います。

問題と解決策

問題解決策
FModel が読み込み/解析中にクラッシュする最新の FModel バージョンを使ってください(古いバージョンは新しいマッピングファイルを読めません)。
Settings で OK を押した後に「Fatal Error … Index was out of range」と表示される無害です – OK で閉じてください。設定は保存されています。
エクスポートがフォルダーに出力されない右下のキューを開いて Export をクリックしてください。Settings の Output フォルダーを確認してください。
Regex 検索で何も見つからない検索欄の Regex アイコンはオンになっていますか? オンにした後、検索欄をクリックして Enter を押してください。
アプリ内でモデルが回転/ずれているFModel の Mesh Format は glTF 2.0 (binary) である必要があります。ツールを再度実行してください。
モデルの代わりに灰色の箱が表示されるこのパーツのモデルがありません(ツールのメッセージ参照)– またはベルト/パイプ/線路/リフトです(意図的にモデルなし)。
