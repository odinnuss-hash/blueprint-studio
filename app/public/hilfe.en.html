Blueprint Studio – Manual

View Satisfactory blueprints outside the game (2D/3D with real game models), edit them, generate new shapes and give all blueprints consistent names. Everything runs locally on this PC.

Start & overview

  • Starting: Double-click start.bat or the desktop shortcut. The app opens in its own window. If you close the window, the program exits by itself after about 25 seconds.
  • At the top you choose the area: Blueprint (view/edit), Building catalog (all buildables with data), Organize (unify names) and Help (this page).
  • Folder opens the current blueprint folder in Explorer, Settings the paths, Save saves changes.

Important: The game reads blueprints when the save is loaded. So after saving or renaming, reload the save. Ideally edit while the game is closed or in the main menu.

Opening blueprints

The folder selection on the left shows all folders under SaveGames\blueprints with their subfolders (indented, e.g. Sortieren › Chaos › Kreativ) and below them the library folders. The folders _Ablage, _Duplikate, _Archiv and _Pakete do not appear there. Even folders with thousands of blueprints open quickly: the list loads more as you scroll, and search and selection (also with Shift across the whole list) apply to all entries.

On the left under Blueprints you choose the Save (session) – this is the subfolder in …\SaveGames\blueprints\ that the game uses for your world (e.g. “MyWorld” – the session name in the save). Below it you see all blueprints with color, size, date and description; the search field filters by name and description. One click opens the blueprint.

The Parts tab lists all part types of the open blueprint with their count. A click selects all objects of that type (with Shift to add to the selection).

2D and 3D view

2D top view

  • Click selects, Shift+click adds, dragging on an empty area = box selection.
  • Dragging the selection = move (on the set grid). Right/middle mouse button = pan the view, mouse wheel = zoom.

3D view

  • Drag with left mouse button = rotate, right mouse button = pan, mouse wheel = zoom, click = select.
  • Hold W A S D = move forward / left / back / right (horizontally in the viewing direction, height stays the same). With Shift three times as fast; the speed adapts to the zoom.
  • Models (toggle at the top): shows the real game models – machines, foundations, walls, roofs, beams, glass (semi-transparent). Off: simple boxes (faster with very large blueprints).
  • With models, conveyor belts are drawn as a flat belt with side edges along their spline, conveyor lifts as an open shaft with a frame; pipelines and hypertubes as tubes, railways as segments. (Without “Models”: simple blocks.)
  • Pen (button at the top or key P): hold the left mouse button and freely outline an area – everything inside is selected. Shift when starting = add, Ctrl = subtract. In pen mode you rotate with the right mouse button. Normally only visible objects are captured; with “including hidden objects” everything whose center lies within the area (also behind/below). If a level is selected, only that level counts. Then Del or “Delete n”; “Done” or Esc ends the pen.
  • The models come from the game (FModel export, see FModel) and are stored, processed, in app\public\modelle.

Levels

For multi-story blueprints the app detects the foundation levels. “Level 2” shows level 2; levels below are shown faded, levels above are hidden.

Rotating / tilting around X, Y, Z

Tool Rotate / Tilt (axis-cross icon in the toolbar): choose the axis – X tilts forward/back, Y sideways, Z rotates like Q/E – and the angle (−90°, +90°, 180° or a custom value). Applies to the selection or, if nothing is selected, to the whole blueprint. “Set back on the ground” keeps the bottom edge the same. Example: tilt an intersection built upright by 90° around X or Y until the roadway is on top, then save it as a new blueprint. In the 3D view you can now also look from below.

Hiding objects

To get at covered parts or parts behind others: make a selection and Hide selection (crossed-out eye, H) – or Show selection only (I), then everything else is gone. Hidden objects cannot be clicked and are drawn neither in 2D nor in 3D. The button “… hidden · show all” (or Shift+H) brings everything back. Hiding does not change the blueprint and is not saved.

Many levels

From eleven levels on, the bar is shown compactly: first level · five levels below and above the selected one · last level, plus arrows ‹ › and a list of all levels with their height.

On the right, the inspector shows name, position, rotation, dimensions, power, recipe (with amounts per minute), color swatch, tier and build cost of the selected object; without a selection, the data of the whole blueprint and its build cost.

Swap material / variant / Mk level

Select objects (e.g. “Parts” tab → all foundations) → on the right Swap parts …. Variants with the same dimensions are offered (Concrete → Asphalt, Grip Metal, Glass; Basic Wall → Window Wall …). Build cost and recipe list are recalculated when saving. Parts marked with * are derived from related parts. Machines (with connections/inventory) cannot be swapped.

Change Mk level (conveyor belts, conveyor lifts, pipelines, pumps)

Select belts/lifts (“Parts” tab → e.g. click “Conveyor Belt Mk.5”) → Material / variant / Mk level … → choose the desired level (Mk.1–Mk.6; pipelines Mk.1 ↔ Mk.2, also without flow indicators; pump Mk.1 ↔ Mk.2). Path, connections and links are fully preserved – only the type and build recipe are replaced. The blueprint's recipe list is extended; the build cost shown in the blueprint header is not recalculated for belts (the game calculates it itself when placing). The level must be unlocked in the save, otherwise the blueprint cannot be built.

Shape generator

Shapes tab on the left: round plate (rings like in-game), circle on the grid, ring/circular track, rectangular area, building (multi-story with walls, window row, roof) and round tower. Size, floors and parts (concrete, asphalt, glass …) can be chosen.

  • Open as new blueprint – preview; changes to the values are visible immediately. Then edit and save as usual.
  • Insert into open blueprint – places the shape on top of the open blueprint (selected, move it with the arrow keys).
  • Pixel art from image: choose an image (PNG, JPG, GIF …), the width in pixels, the pixel size (0.5 / 1 / 2 m), wall or floor, optionally glowing. Each pixel becomes a square sign in the image colour (like the community pixel-art blueprints); transparent pixels can be left out. Below the settings you see the scaled-down image, View in 3D shows the wall, Save as blueprint stores it. At most 20,000 pixels – small images with clear colours work best.
  • Building from floor plan (image): draw the floor plan on a grid (e.g. in Paint, one square = one 8 × 8 m foundation) – black lines = wall, blue = window, red = door, gap = open passage. Choose the image and set “Width (foundations)” to the number of squares across the image width. The check image shows the grid, the detected walls/windows/doors and in green the floor areas (everything inside a closed outer wall). Then choose floors, floor height and parts; windows and doors sit in the lowest wall row of each floor. The top of the image is at the back of the blueprint when you look in the same direction as at the image while placing it.

Saving

  • Save as new blueprint (recommended): copy with a new name in the same save folder, including .sbpcfg with description and icon.
  • Overwrite original: the original is first backed up to userdata\sicherungen\.
  • All data that was not edited (recipes, colors, connections …) stays unchanged – byte for byte.
  • Blueprints from the library or from subfolders (opened via “Organize” with 👁) can also be edited; the copy ends up in the same folder as the original.

Building catalog

All buildings from the game data (CommunityResources\Docs\de.json): category, “unlocked up to tier”, building material, dimensions, power, build cost and all recipes with amounts per minute. Filters on the left by category, tier and material; “Show architecture variants” also shows all material variants of foundations, walls etc. The icons come from the FModel export (app\public\icons).

Organize – give all blueprints consistent names

The Organize area reads in all blueprints: all save folders under SaveGames\blueprints (with subfolders) and the library folders from the Settings (e.g. …\Meine Blaupausen). Folders named _Archiv, _Pakete or _Duplikate are skipped.

  1. Reading in: The first time it takes 20–60 seconds depending on the number, after that it is fast (cache).
  2. Check suggestions: For each blueprint there is a new name following the scheme. Reason “from name” = derived from the old name; “from content” = the old name was meaningless (e.g. 2025_10_10 13_40_24), the suggestion comes from the content (product, machines, parts, dimensions) – please look at these especially carefully. The filter “Name from content (check!)” shows only these.
  3. View: The eye 👁 opens the blueprint in 2D/3D (view only). Go back via the “Organize” area – your entries are kept.
  4. Adjust: Change the new name directly in the row. Red outline = does not fit the scheme (too long, forbidden characters, no group code). Your own changes are remembered immediately, even if you close the app.
  5. Duplicates & similar: The app compares not only the names but the content: which parts are at which position (1 m grid, regardless of where the blueprint is located).
    • Identical (≥ 99 % the same) in the same folder: the worse-named one is suggested as “Duplicate” and, when applying, moved to _Duplikate – not deleted; the game does not see subfolders.
    • Very similar (90–98 %): only a note (“93 % similar to …”), e.g. a variant with a few more signs. You decide yourself (set the action to “Duplicate” or rename).
    • Identical blueprints in different folders (game and library) get the same name.
    The filter “Duplicates & Similar (with preview)” shows two small top views next to each entry: on the left this blueprint, on the right the identical/similar one – so you can see immediately whether it really is a duplicate.
  6. Apply: Set checkmarks (preselection: everything pending) → Apply selected. .sbp and .sbpcfg are renamed together.
  7. Undo: Log / Undo shows every operation; one click restores all old names and locations.

Close the game or leave it in the main menu before applying. Tip: work in stages – e.g. first the filter “Location: Library”, then one group after the other.

Actions, pre-sorting & moving to the archive

  • Actions per row: Rename (or already fits), Sort in (the name fits, only the folder changes), Duplicate → _Duplikate and Delete → recycle bin (into the Windows Recycle Bin, restorable from there). The filters “Sort in only” / “Delete only” show exactly these.
  • Duplicates are only suggested when the parts are identical (same type and count) and the shape matches ≥ 99 %. Intermediate states of large builds with a few extra parts only count as “similar”.
  • Pre-sorting in the library: blueprints from an inbox folder of the library (name starts with “_”, e.g. _sortieren) are placed straight into the archive structure inside that folder when applied, e.g. _sortieren\1 Bauen\1_3 …. The target folder is shown below the new name. All duplicates go to _sortieren\_Duplikate (equal names get “(2)”), folders that become empty go to the Windows Recycle Bin.
  • Move to archive (n): moves everything pre-sorted with the same folder path into the archive in the game folder. If a name already exists there, the blueprint stays in the library and is reported.
  • Renaming, sorting in and duplicates can be undone via Log / Undo, deleted ones via the Windows Recycle Bin.

Archive – sort blueprints in and switch them on/off

At the bottom of the Blueprint area is the Archive (expand and collapse it with the arrow). On the left are the folders according to the naming scheme (1 Building … 9 Special with their subgroups) and your own folders (◆).

  • Archiving: Drag a blueprint from the list on the left onto a folder. It is taken out of the save folder and moved to …\SaveGames\blueprints\_Ablage\<folder>. The game then no longer sees it. The folder is only created when something is put into it.
  • Move into game: Click the toggle next to the blueprint (green = in game). It moves back into the save folder it came from. With the checkbox on the folder (left) or “All into game / Archive all” this works for the whole folder including subfolders.
  • Move into game – which save? The game only shows blueprints from blueprints\<save> (the folder is named like the session in the save, e.g. MeineWelt). The app reads the session names from your saves. Under Settings → Save for “Move into game” you set one; with “Ask every time” a list of all saves appears when activating (with “Remember as default”). Collection folders such as Bauen or Deko are not saves – if an activated blueprint is located there, the archive shows “⚠ not in game”; switching the toggle off and on again moves it into the correct save. In the folder selection on the left, the saves are listed in their own group.
  • Position & size: Under Settings → Archive folder you choose whether the archive is at the bottom or left of the blueprints (full height) across the full height of the app (folders on top, content below). Width (left) and height (bottom) can be adjusted with a slider – or by dragging the edge of the archive directly with the mouse; double-clicking the edge restores the default.
  • Expand all / Collapse all (at the top of the archive): expands or collapses all folders at once.
  • Several at once: In the blueprint list on the left, add individual ones with Ctrl+click, a whole range with Shift+click. Below the list “n selected” appears. If you drag one of the selected blueprints onto an archive folder, all selected ones move along. Right-click, Del or the Delete button deletes all selected ones after a confirmation (to the Recycle Bin). Esc or Clear clears the selection.
  • Sorting in from the library: At the top of the folder selection, under Library, all subfolders of your blueprint library (e.g. …\Meine Blaupausen) are individually selectable. If you drag a blueprint from there onto an archive folder, it is copied to …\SaveGames\blueprints\_Ablage\<folder> – the original stays in the library. To activate it, it is moved into the most recently chosen game session.
  • Re-sorting: Drag a blueprint from the archive onto another folder. If you drag it onto the list on the left, it is activated.
  • Custom folders: “+ Custom folder” or “+ Subfolder”. Empty custom folders can be removed again.
  • Viewing: Double-click or “view”. Archived blueprints are only displayed; to edit them, first move them into the game.

Nothing is ever deleted, only moved (.sbp and .sbpcfg together). The app remembers which blueprint is actively sorted into which folder in userdata\ablage.json. If the game is running, it only sees changes after the save is reloaded.

Deleting blueprints

Trash-can button at the top right of Name & Archive, the trash can on a blueprint in the archive, or right-click on a blueprint in the list on the left. After a confirmation it goes (together with its .sbpcfg) to the Windows Recycle Bin and can be restored from there. If that does not work, it ends up in userdata\papierkorb.

Name suggestion

When a blueprint is opened, Name & Archive at the top right shows a suggestion following the scheme – split into three fields: Category _ Subcategory _ Name. The app inserts the underscores itself (spaces in the name also become underscores). Clicking into “Category” shows all categories (1 Building … 9 Special), clicking into “Subcategory” shows the subgroups of the chosen category – clicking one applies it, or simply type something yourself (typing filters the list, arrow keys + Enter select). Below that is the finished name with a character counter (max. 32); “Archive” follows the chosen category. Renaming sorts it in at the same time: the blueprint immediately ends up in the matching archive folder (from the game: archive, from the library: copy, from the archive: move) – can be turned off in Settings; “Archive” remains for blueprints that are not renamed. Custom folders with a number (e.g. 2_7 Water Treatment under 2 Production) appear in the selection and in the archive at the correct position in the order (marked “custom” at the end). Rename renames the file, Archive puts it straight into the matching folder. The suggestion learns from your own names:

  1. If the blueprint is ≥ 90 % identical to one that is already properly named, its group is used (at 100 % there is the note “probably a duplicate”).
  2. Words in the name that you have often used in a particular group (e.g. “Signpost” → 4_7) determine the group.
  3. For meaningless names (date, “New” …) similar content to your blueprints counts.
  4. Otherwise the fixed rules from the “Organize” area apply.

Every renaming you do here or in “Organize” feeds into the next suggestions (userdata\namen-gelernt.json).

Large window, tiles & show/hide

  • Large window: button Large window at the top of the archive – handy on small screens. Folders on the left, contents on the right; everything works as usual. Close with ✕, Esc or a click outside.
  • List or tiles: switch at the top of the large window. Tiles show each blueprint with a small 3D preview (real models if enabled). Clicking a tile opens the blueprint and closes the window – reopen it via “Large window”. The app remembers your choice.
  • Hide archive: the button Hide archive next to “Folder” hides the folder bar completely (more room for 2D/3D); the same button (Show archive) brings it back.
  • Folder (top) always opens the main blueprints folder …\SaveGames\blueprints in Explorer.
  • When hidden: while the archive is hidden, the button Large window appears next to it at the top – it opens the archive straight in the large window.
  • Editing: a blueprint from the archive can be edited directly (rotate, move, swap …). Save puts the copy into the same archive folder; when overwriting, a backup is made first.
  • Multiple selection: in the archive file list a click selects a blueprint, Ctrl+click adds or removes single ones, Shift+click a whole range, Ctrl+A all. Selected ones can be dragged together onto a folder or the list on the left; the bar above offers Into game, Archive, Delete (also Del) and Clear (also Esc).
  • Renaming when moving: if you drag a blueprint into a folder of another group (e.g. from 1_1 to 2_6), the app adjusts the group code at the front of the name: 1_1_House → 2_6_House. Topic subfolders use the code of their folder; names and folders without a code stay unchanged.

Categories in the game (blueprint menu)

When you bring blueprints from the archive into the game, the app sorts them into the game’s blueprint menu right away: main group → category (e.g. “Building”), subgroup → subcategory (e.g. “Buildings & halls”); the topic subfolders of the archive do not exist in the game. The game stores this layout in the save – so the app changes the newest save of the session (often an autosave) and backs up the original once to userdata\sicherungen\spielstaende beforehand.

  • Keep the game closed: if the game is running, the app remembers the change and applies it as soon as the game is closed (keep the app open). Then load the newest save.
  • Icons: set an icon once per category in the game (“Change”) – the app reads it next time and uses it for new saves as well. The default is the house.
  • Categories you created yourself in the game are kept. Blueprints without a group are listed under “Undefined”.

Planner – calculate and build production chains

In the Planner you enter on the left what should come out (+ Target, amount per minute) and what already arrives finished (+ Supply, e.g. 120 iron ingots/min from the belt next door). The app calculates all production stages, machines, raw materials and the power demand.

  • Graph / list: the graph shows the chain as boxes. Drag boxes = move, click = choose recipe (alternate recipes too – they must be unlocked in the game), drag background / mouse wheel = view. Fit and Rearrange help with large chains; Default recipes resets all recipes.
  • Create blueprint … (or ▣ on a box): either the whole factory (rows stacked, connected with belts and conveyor lifts), a partial factory up to one stage or a single stage as a machine row with splitters, mergers, foundation, power and signs. Choose name, save and the highest belt tier, look at it in 3D first, then Save as blueprint.
  • Basis: when you open a blueprint built in the planner, the planner shows its plan (“Basis of the blueprint”) – Use as my plan or Back to my plan.
  • Layout: compact, as measured in your own blueprints – machines right next to each other, splitters/mergers 2 m in front of the connector, each further line 4 m farther out and 2 m higher, pipes always above the belts. In front of each machine, outside the lines, stands a power pole. Belts, lifts and pipes are sized for all machines at 100 % (not just the planned share); connections between rows carry the full amount of the supplying row.
  • Pipes & fluids: pipe routes with corners are one pipe with bends (as the game builds them). If two rows are next to each other the pipe goes straight across, otherwise through the pipe column on the right. If a pipe rises higher than 9 m, the planner adds a pump (with power; Mk.2 if it goes very high). Fluid by-products run into a fluid buffer, solid ones into an AWESOME Sink.
  • Water & several sources: if an item comes from several rows, all of them are connected (belts via one merger each, pipes via one junction each from above). Whatever the factory produces itself (e.g. water from the aluminium chain) is used first; only the remainder comes from outside – for pipes via a junction with one connector pointing up (sign “ZULAUF VON OBEN”). With Build water extractors too in the dialog, the planner places extractors with power for the missing water (120 m³/min each; the game only allows this via blueprints).
  • Limits: some buildings have no row plan yet (greyed out, hover to see why) – free inputs/outputs with signs are created there. Blueprints made by the planner are never used as part templates; if a template has items in its inventory, save a blueprint with the empty building in the game.

Master Class – ready-made textbook factories

Master Class … in the planner shows cleanly built template factories by tier (highest milestone needed) and topic. The source are the Master Class folders (default: blueprints\Sortieren\Tschukki and the archive “10 Master Class”).

  • Click a template: end products, supply and machines; View in 3D, Copy into the game (into a save) or Use as target (the end products become targets in the planner).
  • Sort into archive files all templates under “10 Master Class” by topic, with the tier in the name.
  • Save package / Load package: save all templates as one file (.bsmc) and load it again on another computer.

Languages

Under Settings → Language: Deutsch, English, Français, 日本語 – the app then reloads; this help exists in all four languages too. The names of your blueprints and folders stay as they are. The names of the archive folders, and therefore of the categories in the game, come from the archive structure (Settings → “Edit structure …”) in the language chosen there; the app remembers the category icons per group number, so they are kept when the language changes.

Map – viewing saves

The Map area reads your saves (.sav, from Update 8 up to version 1.2 – very large old saves need a lot of memory when opened) from …\FactoryGame\Saved\SaveGames\<number> and shows everything built as a top view: buildings, foundations, walls and pillars (including the “lightweight” parts that the game stores collectively), conveyor belts, pipelines, railways and hypertubes as lines, power lines and your character (red cross).

  • Choose the save on the left. The first time it is opened, reading takes a few seconds; after that it comes from the cache (userdata\karten) as long as the file does not change.
  • Drag = pan, mouse wheel = zoom, click = show part (name, position, height, count in the save). “Fit” shows your builds, “Whole world” the whole map (grid = 500 m).
  • Switch Levels on/off on the left (e.g. foundations off to see machines). Resource nodes are off initially.
  • Highlight a part: type a name into the search field (e.g. “Constructor”) – matching parts stay colored, floors are dimmed. On the right, “Most common parts” is clickable.
  • Map (checkbox at the top): game world as background. The four tiles are located in userdata\kartenbild (Map_0-0 … Map_1-1, each 3.75 × 3.75 km).
  • Height from – to (meters): shows only parts in this range, e.g. a single floor of a large factory.
  • On the right, Buildings by type: all machines, generators, storage, trains etc. with their count. Checking them highlights them, everything else is dimmed (several checkmarks possible; the checkmark on the group takes the whole group, e.g. all pipelines). “All normal” (at the top) or Esc undoes this.
  • Open in 3D: opens the save in the 3D editor “Satisfactory 3D Map” (see below).

The map itself does not change the save.

Copying out an area as a blueprint

  1. Open a save, and use levels and Height from – to to set what should be included (e.g. hide foundations or only one floor).
  2. Choose a tool: Rectangle (drag it open; also works at any time with Shift + drag) or Pen (freely outline the area with the mouse button held down – releasing closes the shape).
  3. On the right are the size and number of parts. View in 3D immediately shows the section in the app's 3D view (with game models, nothing is saved). Save as blueprint stores it in the chosen folder; “open in blueprint” shows the result.
  • Buildings (machines, belts, pipelines, storage, signs …) are taken over 1:1 – with recipe, settings, connections and links within the area.
  • Foundations, walls, pillars, beams are stored collectively by the game (“lightweight”); they are rebuilt from your blueprint templates. Beam lengths are kept, colors/patterns are not. Parts without a template are skipped and reported.
  • Power lines only if both ends lie within the area. Connections to parts outside are dropped.
  • The blueprint is aligned to the center of the area (8 m grid) and bottom edge 0. Large areas need mods like Blueprint Designer Plus in the game.
  • This does not work (yet) from Megaprints – use a save for that.

Map image from your own game (FModel)

  1. In FModel (see FModel) go to FactoryGame/Content/FactoryGame/Interface/UI/Assets/MapTest/SlicedMap.
  2. Select the four textures Map_0-0, Map_0-1, Map_1-0, Map_1-1 → right-click → Save Texture (PNG).
  3. Run werkzeuge\kartenbild-uebernehmen.bat. It looks for the images in the FModel export and puts them into userdata\kartenbild (old images are kept as .alt).

3D editor “Satisfactory 3D Map”

A standalone open-source program (GPL-3.0) by moritz-h that shows all objects of a save in 3D and lets you edit their properties. Blueprint Studio only launches it with the chosen save.

  1. Download the latest Windows version from github.com/moritz-h/satisfactory-3d-map/releases (v0.10 or later for saves from 1.2).
  2. Unpack it, e.g. to werkzeuge\Satisfactory3DMap – the app finds it there by itself. If it is somewhere else: fill in Settings → 3D editor with the folder or the .exe.
  3. Choose the save on the map → Open in 3D.

When launching it, Blueprint Studio configures the 3D editor to load the real game models from your game files (can be turned off in Settings). For this it needs the file oodle-data-shared.dll; the app copies it automatically from your FModel folder (FModel downloads it itself on first start). If it is missing, the editor starts without game models. The 3D editor is a separate program with its own window – for a quick look without switching windows, the map has “View in 3D”.

Caution: You save changes there yourself. Back up the save beforehand and do not have the same save open in the game at the same time.

Megaprints (.cbp)

Megaprints are exports from satisfactory-calculator.com (file extension .cbp, compressed JSON with all objects including position and properties). The map lists them below the saves (folder in Settings, e.g. …\Megaprints, without _Archiv) and shows them at their original position on the world map – with levels, highlighting and “Buildings by type”. Even very large Megaprints (400 MB JSON, 300,000 parts) are read in about 2 seconds. Belts and pipelines appear as dots instead of lines for now.

Duplicates & Recycle Bin

In the Organize → “Duplicates & Recycle Bin” area:

  • Duplicates: all blueprints that were moved to _Duplikate while organizing (game folders and library). Put back returns them to their old folder; if the name there is taken in the meantime, the app asks for a new one.
  • Deleted: all blueprints deleted in the app with origin and time. What is in the Windows Recycle Bin you restore there (“Open Windows Recycle Bin”); what was stored as a fallback in userdata\papierkorb, directly here.
  • Nothing is permanently deleted in the app – you do that yourself if needed (empty the Recycle Bin or delete the _Duplikate folders in Explorer).
  • Entire Organize runs can still be reverted under Log / Undo.

Setup (wizard) & distribution

On the first start the setup wizard opens (available again at any time: Settings → Setup wizard). It guides you through everything necessary in a few steps:

  1. Language – Deutsch (default), English, Français or 日本語. The names of buildings and items then also come from your game in this language. Change it later under Settings → Language.
  2. Folders – save folder (default: %LOCALAPPDATA%\FactoryGame\Saved\SaveGames) and Satisfactory installation. The app searches by itself in the Steam libraries, at Epic and on all drives; “Choose …” opens the Windows folder dialog. Green checkmark = found. Optional: your own blueprint collection and Megaprints folder.
  3. Save – into which save “Move into game” puts the blueprints (or ask every time).
  4. 3D rendering – simple boxes (ready immediately) or real game models.
  5. Game models (only when “real game models” is chosen) – automatically with one click on “Fetch models automatically”: on first use the app installs Microsoft's free .NET 10 SDK (Windows may ask for permission), downloads the free library CUE4Parse (the same one FModel uses), builds a small helper program from it (werkzeuge\extraktor) and uses it to take part data, 3D models and icons straight from your game installation. Progress and output are shown in the window; about 5–15 minutes the first time, much faster afterwards. If that does not work, the manual guide with FModel is still available below (install .NET Desktop Runtime 10, download FModel, enter the values – each with a Copy button –, click three exports, “Import”).
  6. Extras – map image, 3D editor “Satisfactory 3D Map”, desktop shortcut.

In addition, Settings → Requirements & Shortcut checks at any time: Node.js, game installation, save folder, app window (Edge/Chrome), 3D models, icons, map image, 3D editor and desktop shortcut – the following can be installed with one click:

  • 3D editor “Satisfactory 3D Map” – latest Windows version from GitHub into werkzeuge\Satisfactory3DMap.
  • Map image – the four tiles from the satisfactory-3d-map project (version 0.6; replace via FModel for the current version).
  • Desktop shortcut – on the desktop and in the Start menu, with icon.

start.bat installs Node.js itself on first start (winget). 3D models and icons are game content by Coffee Stain Studios: they must not be published along with the app and are fetched once by each user from their own game installation – automatically in the wizard or manually with FModel (FModel guide).

Updates

Blueprint Studio checks GitHub for a new version on start (at most every 6 hours). If there is one, the ⬆ Update button appears at the top: it shows what is new and installs the update with Update now. The app then reloads and restarts its server by itself. Manually: Settings → Updates → Check for updates now.

  • Kept: settings and everything in userdata, your blueprints, 3D models, icons, FModel, the 3D editor and the extractor files.
  • Backup: every program file that is replaced is first copied to userdata\update-sicherung\<old version> – to go back, simply copy these files into the program folder again.
  • Source: the releases of the GitHub project, set in app\update.json; another source can be entered in the settings. Automatic checking can be switched off there as well.

Publishing (e.g. GitHub)

The file .gitignore in the program folder excludes everything that must not be published or is personal: userdata, models, icons, map image, FModel, the 3D editor and blueprints/saves. The help contains no fixed paths – it always shows the folders from your own settings.

Releasing an update: increase the version number in app\server.mjs (VERSION) and app\public\js\main.js (APP_VERSION), upload (GitHub Desktop: Commit → Push) and publish a release on GitHub under Releases → Draft a new release with the tag v + version number (e.g. v1.1.0) and a short description of what is new. All installed apps then offer the update on their next start.

Settings

  • Save folder (contains blueprints): default %LOCALAPPDATA%\FactoryGame\Saved\SaveGames.
  • Satisfactory installation folder (contains CommunityResources): on your system: …\steamapps\common\Satisfactory (searched for on first start).
  • Additional blueprint folders (library): one per line, e.g. …\Meine Blaupausen. Included in “Organize”.
  • Language: Deutsch, English, Français, 日本語 – the app then reloads.
  • Archive folder structure (“Edit structure …”): list of all main groups (7) and subgroups (7_3) – the default is the bundled structure plus your own numbered folders. Change names, add entries (“+ Main group”, “+ Sub”) or remove them; “Restore default” resets. When saving, existing folders in the archive are renamed accordingly (content is kept); removed entries do not delete any folders. The numbers are at the front of the blueprint name.
  • Prefixes: words such as your player or world name that should be dropped from the front in the name suggestion (separated by commas).
  • Updates: check automatically on start (on/off), update source on GitHub (owner/repository, empty = app default) and “Check for updates now” – see Updates.
  • View when opening a blueprint: Last used view (default – the app remembers whether you last had 2D or 3D), Always 2D (top view) or Always 3D. Switching with the 2D/3D buttons or the keys 2/3 still works at any time.

Limitations & notes

  • When machines are moved, conveyor belts/lines stay in their old place – move connected groups together (box selection).
  • Machines cannot be swapped or newly created, only architecture parts.
  • Blueprints from older game versions (Update 7/8) are also read. Parts from mods appear as gray boxes.
  • Names in the game are limited to 32 characters – that is why “Organize” shortens automatically.

Rules & examples

  • Max. 32 characters (input limit in the game). No characters \ / : * ? " < > |. Umlauts are allowed.
  • Underscores separate the parts; words start with a capital letter (Leergebäude_Japanisch12), short connecting words stay lowercase (Beton_für_Stahlbeton).
  • Quantity at the end: 10x Band → 2_2_Band_10x. Ratios compact: Balancer 4 zu 4 → 2_3_Balancer_4zu4.
  • Production: product first, then machines/rate: 2_1_Eisenbarren_10xSchmelze, 2_1_Platine_5x_150pm (pm = per minute).
  • Multi-part sets keep their set name: 8_6_COC_Kran_2_Teil2, 1_1_HouseBeckenbauer_2Teil_Turm_Links.
  • Personal prefixes (e.g. PlayerName_, WorldName_ – enter them in Settings under “Prefixes”, also 270_) are dropped – the group says more. Community names stay in their language, only cleaned up (without “[1.2 Vanilla]”, “v1.1”, “by …”).
  • Duplicates do not get their own name but move to _Duplikate.

Checklist for a game update (version change)

After a larger Satisfactory update (e.g. 1.2 → 1.3), go through these steps in order. Small patches usually only need steps 1–3.

  1. Start the app and check the catalog. Blueprint Studio re-reads CommunityResources\Docs\de.json at startup as soon as the file has changed. In the “Building catalog” area, the number of buildings/items/recipes is shown at the bottom left. If an error appears: Settings → check the installation folder.
  2. Open a blueprint that was saved in the new game version. New game versions sometimes change the file format. If it opens, everything is fine. If not: note the message – the reader (app\lib\sbp.mjs) must be adapted.
  3. Rebuild templates. Delete the file userdata\vorlagen-cache.json and restart the app. This lets the app learn new parts from your current blueprints/saves (for the shape generator and swapping).
  4. Test shapes/swapping. Generate a small shape, save it, place it in the game. If that works, everything is compatible.
  5. Update FModel. Unpack the latest version from fmodel.app (or GitHub releases) to …\werkzeuge\FModel – or use “Download FModel” in the setup wizard. Under Settings check the UE version (Satisfactory 1.2: GAME_UE5_6 – for a new engine choose the matching one) and set the path to the new mapping file CommunityResources\FactoryGame.usmap.
  6. Re-export icons (only needed for new items/buildings): FModel → Icons, then werkzeuge\icons-uebernehmen.bat.
  7. Re-process 3D models (only for new/changed buildings): export part data and models, then werkzeuge\modelle-aufbereiten.bat. It reports missing meshes, which you then export specifically.
  8. Re-read Organize. The cache userdata\ordnen-cache.json renews itself automatically; delete it if there are problems.

FModel – download & setup

FModel is a free viewer for Unreal Engine game files. It lets you get icons, 3D models and part data out of Satisfactory.

Easier: the setup wizard (step “Game models”) fetches the same data with Fetch models automatically – no FModel needed. You only need the following guide if the automatic way does not work for you.

  • Download: https://fmodel.app/ – or the releases on GitHub: github.com/4sval/FModel/releases. Guide/wiki: github.com/4sval/FModel/wiki.
  • Satisfactory-specific guide by the modding community: docs.ficsit.app → Extract Game Files.
  • Requires the .NET Desktop Runtime 10 (FModel asks for it on first start; the wizard installs it with one click).
  1. Unpack to …\werkzeuge\FModel (the setup wizard does this automatically) and start FModel.exe.
  2. Add the game: In the “Directory Selector” window create an Undetected Game: name Satisfactory, folder …\steamapps\common\Satisfactory, blue plus, OK.
  3. UE version: GAME_UE5_6 (Satisfactory 1.2). If it is not offered: turn off “Enable custom UE versions”.
  4. Settings → General:
    • Output Directory: …\werkzeuge\FModel\Output
    • Keep Directory Structure: on
    • Local Mapping File: on, path …\Satisfactory\CommunityResources\FactoryGame.usmap
    • Optional: Custom Versions – paste the content of CommunityResources\CustomVersions.json (the file is UTF-16).
  5. Settings → Export (Models): Mesh Format = glTF 2.0 (binary), Texture Format = PNG, Auto-Export Attached Materials = off (saves space). OK.
  6. Load: Archives tab → Load. Afterwards the Folders and Packages tabs are filled.

Exporting in newer FModel versions: Exports first go into a queue (yellow field at the bottom right of the status bar). Click it → “Export Session” window → Export. The counter shows the progress.

Exporting icons

  1. Open search: menu Packages → Search (Ctrl+Shift+F).
  2. Search: enter IconDesc, Enter. (About 1,500 results.)
  3. Select all: click the first result, Ctrl+A.
  4. Export: right-click → Export → Texture. Then queue at the bottom right → Export.
  5. Import into the app: double-click werkzeuge\icons-uebernehmen.bat. It copies exactly the icons the catalog needs and reports missing ones.
  6. Fetch missing ones: The tool outputs a line like /(Hub_512|Track_512|…)\.uasset$. In the FModel search, turn on the Regex icon (second icon on the right of the search field), paste the line, Enter, export as texture as above and run the tool again.

Exporting part data (for the 3D mapping)

The app needs to know which model belongs to which part and how it is positioned. This is stored in the game's Build_* blueprints.

  1. Open search, Regex on, enter: 
    Buildable/.*/Build_[^/]*\.uasset$
  2. Select all → right-click → Export → Properties (json). These exports are saved immediately (about 590 files).

Exporting 3D models

  1. Search, Regex on: 
    Buildable/(Factory|Building)/.*/SM_[^/]*\.uasset$
  2. Select all → right-click → Export → Model. Queue → Export (about 500 models, a few minutes).
  3. Double-click werkzeuge\modelle-aufbereiten.bat. It reads part data + models, converts them to game coordinates and writes app\public\modelle\ (~40 MB).
  4. If the tool reports missing meshes (e.g. ConstructorMk1_static), search for these names via regex and export them as Model as well: 
    Buildable/.*/(ConstructorMk1_static|SmelterMk1_static)\.uasset$
    Then run the tool again.
  5. Reload Blueprint Studio – use the Models toggle in the 3D view.
